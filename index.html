170+ 工具函数

覆盖类型判断、数组、对象、字符串、日期、数字、URL、颜色、编码、加密等场景。

轻量级

核心零依赖，打包体积小，按需引入（SM2/SM4 可选依赖 sm-crypto）。

模块化

主包全量平铺所有方法，支持按需导入与 Tree-shaking；子路径保留用于向后兼容。除 crypto 外的全部方法均可从主包导入。

TypeScript

完整的类型定义，享受类型安全的开发体验。

双模块格式

同时支持 ESM 和 CJS，兼容各种构建工具。

Tree-shaking

完整支持 Tree-shaking，只打包用到的代码。

快速开始 ​

全量平铺（推荐） ​

所有模块的方法均可直接从主包导入，配合 Tree-shaking 只打包用到的函数：

typescript
// 类型判断、数组、字符串、日期等核心工具
import { isArray, dateFormat, isEmpty } from 'l-js-fn';
// 浏览器 BOM / WebSocket / 存储 / 轮询 / 事件总线等子模块方法
import { scrollTop, WebSocketManager, getStorage, Polling, EventBus } from 'l-js-fn';
// 常量与正则
import { DATE_FORMAT, REGEXP } from 'l-js-fn';

除 crypto 外，所有子模块方法均已平铺到主包。主包为 ESM 具名导出且 sideEffects: false，现代打包器（webpack5 / vite / rollup / esbuild）会摇树到函数级，只打包实际使用的方法。

uniapp 命名说明：为与通用命名（env、file、request 等）区分，uniapp 方法在主包中统一带 uni 前缀，如 uniEnv、uniFile、uniRequest、uniStorage、uniClipboard、uniDevice、uniNetwork。子路径 l-js-fn/uniapp 仍保留原始命名。

子路径导入（兼容旧用法） ​

l-js-fn/<module> 子路径仍保留，可用于 CJS（require）或需要精确控制加载的场景：

typescript
import { scrollTop, copyToClipboard } from 'l-js-fn/bom';
import { WebSocketManager } from 'l-js-fn/ws';
import { Polling } from 'l-js-fn/polling';

crypto 模块（仅子路径） ​

crypto 模块依赖 Node 内置 crypto（MD5/AES/RSA）与可选依赖 sm-crypto（SM2/SM4），仅在 Node 环境可用，因此不参与主包平铺，始终通过子路径导入：

typescript
import { md5, aesEncrypt, sm2Encrypt, sm4Encrypt } from 'l-js-fn/crypto';

常见问题 ​

是否支持服务端/SSR 环境？ ​

大部分工具函数（is-kit、array-kit、string-kit、object-kit、date-kit、number-kit、url-kit、common、color、regex、config、encode）可以在任何 JavaScript 环境中使用。

以下模块仅在浏览器环境中可用：

  • bom（DOM 滚动、全屏、剪贴板、Cookie）
  • file（文件下载、读取）
  • storage（localStorage/sessionStorage）
  • ws（WebSocket）
  • ipc（iframe 通信）
  • polling（定时轮询）

isImage 在多个模块中出现，应该用哪个？ ​

isImage 定义于 is-kit，file 模块对其做了转发导出，功能一致（均支持 13 种常见图片格式）。建议：

  • 主包用户直接使用 import { isImage } from 'l-js-fn'
  • 子模块用户使用 import { isImage } from 'l-js-fn/file'
  • 两者行为完全相同

Result 类哪里去了？ ​

Result 类已在 v4.0 移除（此前仅 arrayMove 与 imageToBase64 使用，且与库整体「返回普通值」的语义不一致）。相关调整：

  • arrayMove 返回纯数组 T[]，无法移动时返回原数组拷贝
  • imageToBase64 返回 Promise<string>，失败时 reject

如需统一封装接口返回结果，建议自行实现或在业务层约定返回结构。
